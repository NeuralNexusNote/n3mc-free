# N3MemoryCore Free v1.6.0 コードレビュー

2026-11-17。対象は `N3MemoryCore_v1.6.0_Free_JP.md` と、同じリポジトリの Python 実装・テスト。コードは変更していない。以下は再現できた問題を重要度順に記したもの。

## 1. [P1] 長文を分割すると元の改行・空白が失われる

- **根拠:** 指示書の §5.1 と §5.4 は、コードブロック以外の会話文を切り捨てず、原文のまま保存する契約としている。`n3memorycore/core/processor.py:135` は段落を `strip()` し、同ファイル `:143-145` は文を分割してから `sep=' '` で結合する。`_merge_chunks()` (`:153-170`) も分割前の区切り文字を保持しない。
- **再現:** `s = ('First sentence. ' * 40) + '\nLine two.'` を `chunk_text(s)` に渡すと、元文字列には改行があるが、返された全チャンクには改行がない。実測したチャンク長は `[399, 290]`。この後にフックが保存するのは変形後の文字列なので、DB から原文を復元できない。
- **影響:** 改行に意味がある設定値、ログ、表、文章の体裁が変わる。監査ログには生の入力が残るが、検索対象の記憶と `--show-turn` の内容は変形される。
- **修正方針:** 原文のオフセットを基準に切り出し、区切り文字を含めて保存する。段落・文の境界は切断位置の選択にだけ使い、保存する文字列を `strip()` や空白結合で作り直さない。

## 2. [P2] `max_chars=400` を超えるチャンクが作られる

- **根拠:** 指示書 §1 と §5.1 はフックのチャンクを `max_chars=400` と指定している。`n3memorycore/core/processor.py:163-166` は前チャンクの末尾40文字と区切り文字を次の段落の前に足すが、加算後の長さを再確認しない。
- **再現:** `chunk_text('x' * 10 + '\n\n' + 'y' * 400)` の返り値の長さは `[10, 412]`。2件目は400文字を超える。
- **影響:** 指定したチャンクサイズが守られず、段落の長さによっては埋め込みモデルの入力上限に近づく。後続の検索が一部の内容を意味検索できない可能性がある。
- **修正方針:** オーバーラップと区切り文字を含めて上限を判定し、必要なら次の段落も分割する。

## 3. [P2] Windows の既存フックを見落とし、`--init` で重複登録する

- **根拠:** 指示書 §4 は既存のこのパッケージのフックを置き換え、再実行を冪等にするよう要求している。`n3memorycore/n3memory.py:2170-2200` の `_hook_tokens()` は Windows のパスにも `shlex.split(..., posix=True)` を使い、引用符のないバックスラッシュをエスケープ文字として消す。`_merge_settings()` (`:2253-2282`) は `is_own_hook()` が偽を返したエントリを残して新しいエントリを追加する。
- **再現:** `is_own_hook(r'C:\Tools\n3mc-hook.exe', 'UserPromptSubmit')` は `False`、`is_own_hook('C:/Tools/n3mc-hook.exe', 'UserPromptSubmit')` は `True`。前者の形式で既存設定に登録されていると、`--init` 後に両方のフックが動く。
- **影響:** `settings.json` に旧エントリと新エントリが併存し、再初期化の冪等性が崩れる。旧コマンドが実際に起動できる環境ではフックが二重に動く。旧コマンドがシェルで解釈できない環境では二重実行は起きないが、無効なエントリが残る。
- **修正方針:** Windows 形式のパスを壊さずにトークン化し、既存の `n3mc-hook.exe` / `n3mc-stop-hook.exe` を確実に認識する。

## 4. [P2] 「Embedding テストを除外」の実行例でもモデル取得が必須

- **根拠:** 指示書 §7 は `python -m pytest tests/ -v -k "not TestEmbedding"` を遅い Embedding テストを除く実行方法として案内している。しかし `tests/test_api.py:9-46` の共通 `client` fixture は各 API テストの前に `get_model('intfloat/multilingual-e5-base')` を必ず呼ぶ。`-k` ではこの fixture を除外できない。
- **再現:** モデル取得先へ接続できない今回の環境では、`tests/test_api.py::TestHealth::test_health_ok` がテスト本体に入る前にモデル取得でエラーとなった。DB層27件、フック21件、追加の検索・ポート関連21件は通過した。
- **影響:** オフライン環境では、モデルと無関係な `/health` などの API テストも実行できない。指示書の「遅いEmbeddingテストをスキップ」という案内に沿っても全体の回帰検証を完了できない。
- **修正方針:** モデルを必要とするテストにだけ読み込みを限定し、通常の API テストでは埋め込みをスタブ化する。実モデルを使うテストを明示的に分ける。
