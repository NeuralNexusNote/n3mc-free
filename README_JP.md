# N3MemoryCore Free (n3mc-free) v1.9.1

**Claude Code に、消えない記憶を。無料で、あなたの PC の中に。**

Claude Code は、会話を閉じると、何を話していたかを忘れます。
N3MemoryCore は、発言と返答をすべて、あなたの PC のファイルに保存します。
次に同じ話をしたとき、関係のある記憶を自動で呼び出します。
あなたが「覚えて」と言う必要も、Claude が検索のツールを呼ぶ必要もありません。
どちらも、フックが毎ターン行います。

1. エクスプローラーで、空のフォルダを作る
2. そのフォルダに指示書 `N3MemoryCore_v1.9.1_Free_JP.md` を入れる(指示書のほかに何も入れない)
3. Claude のデスクトップアプリで **Code** タブを開き、**+ New** で新しいセッションを始め、**Local** を選んでから **Open folder…** でそのフォルダを選ぶ(ターミナルでは、そのフォルダに移って `claude` を起動する)
4. 「この指示書 `N3MemoryCore_v1.9.1_Free_JP.md` に従って N3MemoryCore を実装してください」と送る
5. 終わったら、Claude Code を再起動する（ウィンドウを閉じるだけでは足りないことがあります。[Claude Code を再起動する](#4-claude-code-を再起動する) を見てください）

再起動のあとは、同じセッションを開いて「再起動しました」と送ってください。記憶が働いているかを Claude Code が確かめ、次にすることを案内します。

次のセッションから記憶が働きます。
最初の 1 回だけ、検索用のモデル（約 1.1 GB）のダウンロードがあります。詳しくは [セットアップ](#セットアップ) を見てください。
PyPI から入れる方法（おまけ）は [方法 B：パッケージ導入（おまけ）](#方法-bパッケージ導入おまけ) にあります。

> **⚠️ 記憶の保持期間とデータ量**
>
> - **記憶は消えません。** Free には、古い記録を消す機能はありません。
> - **データ量が増えると遅くなります。** 記録が増えるほど、検索に時間がかかるようになります。

## 仕組み

```
ユーザーの発言
    │
    ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  1. 自動保存  │────▶│  2. 意味検索  │────▶│ 3. コンテキスト│
│  前回の回答を │     │  関連する過去 │     │    注入       │
│  DBに保存    │     │  の記憶を取得 │     │  Claudeに渡す │
└──────────────┘     └──────────────┘     └──────────────┘
                                                 │
                                                 ▼
                                          Claudeが過去の
                                          文脈を踏まえて回答
```

Claude Codeのフック機能を利用し、すべて自動で行われます。ユーザーが意識する必要はありません。

- **保存するもの** — あなたの発言と Claude の返答を、すべてそのまま保存します。コードブロック（``` で囲んだ部分）は `[code omitted]` として保存します。N3MC が覚えるのは、話したことと決めたことです。コードは、プロジェクトのファイルにあります。Claude Code 自身が差し込む入力（タスクの通知、エージェントのメッセージ、システムの注意書き）は保存しません。
- **呼び出すもの** — 発言のたびに、フックが記憶を検索します。関係のある記録を、Claude があなたの発言を読む前に、コンテキストに加えます。

### 3 つの場面

> **月曜** — Claude Code と相談して、サイトのデータベースを PostgreSQL にすると決めます。理由も話します。
>
> **水曜** — 新しいセッションで、「データベースは何にしたか」と聞きます。月曜の決定と理由が、質問と一緒に Claude に届きます。説明し直す必要はありません。
>
> **金曜** — 別のフォルダで作業しています。その話題になると、月曜の決定がここでも呼び出されます。Free は、すべてのプロジェクトのフォルダで 1 つの記憶を使います。

### 実際に Claude に届くもの

水曜の質問のときに、フックが加えた塊です。フックを実際に動かして取ったものです（一時的なデータフォルダを使い、2 つ目のセッションは 1 つ目と別のフォルダで始めました）。

```text
# Recalled Memory Context
Search query: サイトのデータベースは、何にすると決めましたか。理由も教えてください。

## Top matches (use these to answer the question)

_If several versions of the same content appear, the one with the newest `saved` time is the current one._

## [1] score=0.5472 saved=2026-11-22 15:59 (UTC+0900) claude-code
[user] サイトのデータベースは PostgreSQL にしましょう。複数の人が同時に編集する予定で、SQLite は書き込みのたびにファイル全体をロックするからです。

## [2] score=0.4779 saved=2026-11-22 15:59 (UTC+0900) claude-code
[claude] 承知しました。データベースは PostgreSQL にします。理由は、同時に編集する人がいることと、SQLite は書き込みが 1 つずつになることです。次は、記事のテーブルの定義を書きます。

## Previous matching Q-A exchanges (supplementary context)

### turn_id: 378a62f3-fff4-4233-9a97-1044f17bf86d saved=2026-11-22 15:59 (UTC+0900)
[user] サイトのデータベースは PostgreSQL にしましょう。複数の人が同時に編集する予定で、SQLite は書き込みのたびにファイル全体をロックするからです。
[claude] 承知しました。データベースは PostgreSQL にします。理由は、同時に編集する人がいることと、SQLite は書き込みが 1 つずつになることです。次は、記事のテーブルの定義を書きます。
```

`Top matches` は、関連度の下限を通った記録です。下限を通った記録が少ないときは、落ちた記録のうち近いものが `Possibly related` という見出しで加わります。最後の部分は、上位の記録が入っているやりとりの全体です。

### Claude標準のauto-memoryとの違い

Claude Codeには標準のauto-memory機能（`~/.claude/projects/.../memory/`）があります。N3MemoryCoreはこれと**競合せず、補完し合います**。

| | Claude auto-memory | N3MemoryCore RAG |
|---|---|---|
| **得意なこと** | 確実・毎回ロード・固定情報 | 過去の会話の文脈・詳細な経緯 |
| **苦手なこと** | 会話の流れや文脈は持てない | 検索精度に依存・確実性がない |
| **用途** | ユーザープロフィール、フォルダパス等 | 会話の詳細、議論の経緯 |

**推奨の使い分け：**
- **毎回必要な固定情報**（開発フォルダのパス、ユーザーの好みなど）→ auto-memoryに保存
- **会話の文脈・経緯**（議論の流れ、過去の決定理由など）→ N3MemoryCoreが自動で蓄積

## Free と Lite、どちらを使うか

無償の N3MemoryCore は 2 つあります。**初めての方は、Free(このリポジトリ)から始めてください。**

| | **N3MC Free**(このリポジトリ) | **[N3MC MCP Lite](https://github.com/NeuralNexusNote/n3mcmcp-lite)** |
|---|---|---|
| 使えるアプリ | Claude Code だけ | Claude Code(フック)と、Claude のデスクトップアプリなど MCP 対応のアプリ(MCP) |
| 保存されるもの | すべての発言と返答を自動で(フック) | Claude Code では、すべての発言と返答(フック)。ほかのアプリでは、AI が保存すると判断したもの(`save_memory`) |
| 残る期間 | 期限なし | 7 日。過ぎると自動で消える |
| 必要なもの | Python 3.10 以上 | Python 3.10 以上、Docker(Redis Stack) |
| 導入 | `pip install n3memorycore-free` の後に `n3mc --init` | Redis Stack を起動し、`pip install n3memorycore-mcp-lite` の後に `n3mc-lite --init`(または Claude Code のプラグイン)。ほかのアプリには MCP の入口を登録する |
| 向いている人 | 初めての方。Claude Code の長期記憶に | Docker を動かせる方。プロジェクトの間だけの作業メモリを、Claude のデスクトップアプリとも共有したい場合に |

- **Free を選ぶ:** Claude Code を使っていて、ほかのソフトを入れずに会話を覚えさせたい場合。
- **Lite を選ぶ:** Claude のデスクトップアプリやほかの MCP クライアント(Cursor など)も使う場合や、短いプロジェクトが終われば自然に消える記憶がほしい場合。Docker を起動できることが前提です。

**次の場合は、Free は向いていません。**

- Claude Code 以外のアプリを使う場合。Free は、Claude Code のフックだけで動きます（上の Lite を見てください）。
- 古い記録を自動で消したい場合や、記録を 1 件ずつ消したい場合。Free には、削除のコマンドがありません（[Free版とPro版](#free版とpro版)）。
- 2 台の PC で同じ記憶を使いたい場合。Free は、1 台の PC の 1 つのファイルに保存し、同期はしません。

## 特徴

| したいこと | N3MemoryCore がすること | 仕組み |
|---|---|---|
| 同じ説明を繰り返したくない | 発言と返答をすべて保存し、関係のあるものを毎ターン呼び出す | Claude Code のフック（`UserPromptSubmit`、`Stop`）。ツールの呼び出しも、手作業も要らない |
| 自分の言葉で探したい | 言い回しが違っても、関係のある過去の会話を見つける | `intfloat/multilingual-e5-base` のベクトル検索（日本語・英語・中国語・韓国語など約 100 言語）と、キーワード検索 |
| 翌日、続きから始めたい | セッションをまたいでも、プロジェクトのフォルダが違っても、記憶が残る | すべてのフォルダで 1 つの DB。今の会話の記録を先に並べる |
| データを手元に置きたい | 記憶を自分の PC のファイルに保存し、クラウドのサービスには置かない | SQLite。Claude に送られるのは、そのターンに呼び出した記憶だけで、メッセージと一緒に送られる（[詳しく](#記憶はあなたの-pc-に残ります)） |
| トークンを節約したい | 検索はローカルの埋め込みで行い（Claude のトークンは使わない）、関係のある記録だけを差し込む | 差し込む塊には上限がある（`top_matches_max`、`min_results`） |
| 複数のエージェントで 1 つの記憶を使いたい | 記録ごとに、書いたエージェントを残す | `agent_name`・`local_id`。エージェント自身の記憶を先に並べる機能は Pro 版のもの |
| あとで上の版に移りたい | Pro が引き継げる DB を作る | 同じ指示書から作った DB は互換。Pro は `n3mc-pro --migrate-from-free` で Free の DB を読む |

ほかの埋め込みモデルを使うときは、`config.json` に書いて `n3mc --reembed` を実行します。768 次元のベクトルを出すモデルである必要があります。

## 記憶はあなたの PC に残ります

AI が覚えていてくれるのは便利ですが、その記憶がどこに置かれるのかは気になるところです。N3MemoryCore は、記憶をあなたが管理できる 1 か所、つまりあなたの PC の中のフォルダに置きます。

- **ローカルの 1 ファイル** — 記憶はすべて、SQLite のファイル `~/.n3mc/.memory/n3memory.db` 1 つに保存されます。N3MC のアカウントも、N3MC のクラウドサービスもありません。置き場所は `N3MC_HOME` で変えられます([オプション: データ位置の変更](#オプション-データ位置の変更))。
- **入力の原文も、その隣に残る** — `~/.n3mc/.memory/audit.log` に、フックが受け取った原文（あなたの発言と Claude の返答。コードブロックも含む）が残ります。50 MB で入れ替わります。`n3mc --list` には出ません。DB と同じく、他人に見せない情報として扱ってください。
- **検索は PC の中で動く** — 埋め込みモデルも検索も、手元で動きます。N3MC のサーバーは `127.0.0.1` だけで待ち受け、ほかのホスト名あての要求は断ります。同じネットワークのほかの機械からは使えません。
- **利用状況を送らない** — N3MC は利用データをどこにも送りません。コードは公開されているので、ご自身で確かめられます。
- **中身を見られる・消せる** — `n3mc --list` で保存された内容を表示できます。`~/.n3mc/` を消せば、すべて消えます([アンインストール](#アンインストール))。バックアップは 2 つのファイルをコピーするだけです([バックアップと復元](#バックアップと復元))。

ネットワークを通るもの:

- **埋め込みモデルのダウンロード** — 最初の検索のときに、`intfloat/multilingual-e5-base`(約 1.1 GB)を Hugging Face から取得します。その後も、モデルを読み込むときに Hugging Face のライブラリが更新を確認することがあります。ダウンロードが済んだ後に `HF_HUB_OFFLINE=1` を設定すると、この確認は止まります。
- **Claude が読む部分** — そのターンに呼び出された記憶はプロンプトに加えられるので、Claude Code に入力した文と同じように、メッセージと一緒に Anthropic に送られます。N3MC が記憶の DB をどこかに上げることはありませんが、Claude がそのターンに使う部分は会話の一部になります。

## セットアップ

導入の方法は以下の 2 通りです。指示書から作成する方法 A がメインで、パッケージを入れる方法 B はおまけです。（方法の名前は指示書と同じです。）

### 方法 A：指示書から作成（メイン・推奨）

指示書から、Claude Code にコードを生成させます：

1. **フォルダを作る**:エクスプローラーで、空のフォルダを 1 つ作ります(例:`C:\Users\<あなたの名前>\n3mc-free`)。コードはこのフォルダに作られ、セットアップのあとも使い続けます。あとで消したり動かしたりしないでください。
2. **指示書を入れる**:ダウンロードした指示書 `N3MemoryCore_v1.9.1_Free_JP.md` を、そのフォルダに入れます(このフォルダには、指示書のほかに何も入れません)。
3. **そのフォルダで Claude Code を開く**:Claude のデスクトップアプリで、サイドバー上部の **Code** タブを開き、**+ New** で新しいセッションを始めます。プロンプト欄の下の行で、環境は **Local** を選び、その横のフォルダの欄で **Open folder…** を選んで、1 のフォルダを選びます。(ターミナルで使うときは、そのフォルダに移って `claude` を起動します。)
4. **頼む**:プロンプト欄に「この指示書 `N3MemoryCore_v1.9.1_Free_JP.md` に従って N3MemoryCore を実装してください」と書いて送ります。

Claude Code は、フォルダを表示して 1 回だけ確認を求めます。そのあと、コードの記述、フックの設定、初期設定のすべてを行います。フォルダにほかのファイルがあるときは、あなたのプロジェクトを上書きしないように、作業を止めます。
セットアップには約15〜30分かかります（環境やモデルにより異なります）。
次のセッションから記憶が有効になります。生成したコードは、そのフォルダに残ります。あとでフォルダを消したり動かしたりすると、記憶が止まります。

### 方法 B：パッケージ導入（おまけ）

リファレンスビルドをそのまま使います：

#### 1. インストール

最も簡単な方法 — PyPI から直接インストール (clone 不要):

```bash
pip install n3memorycore-free
```

ローカルにコードを取得してカスタマイズしたい場合:

```bash
git clone https://github.com/NeuralNexusNote/n3mc-free.git
cd n3mc-free
pip install -e .          # editable install
```

editable install では、フックがそのフォルダのコードを動かします。あとでフォルダを消したり動かしたりすると、記憶が止まります。

要件: Python 3.10+。サーバー初回起動時に埋め込みモデル（`intfloat/multilingual-e5-base`、約 1.1 GB）をダウンロードします。回線によりますが、最初の 1 回だけ数分かかります。

#### 2. Claude Code に接続する

```bash
n3mc --init
```

このコマンド一発で、N3MC を Claude Code に接続するために必要な処理を**すべて**実施します:

- `~/.n3mc/` を作成（DB・設定・監査ログ・PID ファイルがここに集約）
- `~/.n3mc/config.json` に `owner_id` / `local_id` を自動生成して書き込み
- **ユーザーグローバル**の `~/.claude/settings.json` に `UserPromptSubmit` と `Stop` フックを登録（インストール済みの `n3mc-hook` / `n3mc-stop-hook` エントリポイントの絶対パスを指し、それぞれに 120 秒の制限時間を付ける）。「ユーザーグローバル」が重要 — リポジトリ内に限らず**どのプロジェクトディレクトリ**で起動した Claude Code セッションでもフックが発火する
- 同じファイルの `permissions.allow` に、記憶のコマンド（`python -m n3memorycore.n3memory --search …`、`--show-turn` など）の許可を足す。どのプロジェクトでも、Claude が確認なしで記憶を検索できる。既存の許可は消さない
- ほかのプログラムのフックには触れない。同じ PC に登録された別の N3MC（Pro など）のフックも残し、見つけたときは 1 行表示する
- 変更する前に `settings.json` のバックアップ（`settings.json.bak-n3mc-<日時>`）を取る。JSON として読めないファイルは変更せず、その旨を表示する

このコマンドは冪等です。再実行しても重複登録されません。以前の版でフックを登録した方は、もう一度実行してください。すでにある登録に、制限時間が足されます。

#### 3. フック登録を検証する

以下のワンライナーを実行 — `OK` が出力されれば成功:

```bash
python -c "import json,os; s=json.load(open(os.path.expanduser('~/.claude/settings.json'), encoding='utf-8')); h=s.get('hooks',{}); assert any('n3memorycore.n3mc_hook' in c.get('command','').lower() or 'n3mc-hook' in c.get('command','').lower() for e in h.get('UserPromptSubmit',[]) for c in e.get('hooks',[])), 'UserPromptSubmit hook missing'; assert any('n3memorycore.n3mc_stop_hook' in c.get('command','').lower() or 'n3mc-stop-hook' in c.get('command','').lower() for e in h.get('Stop',[]) for c in e.get('hooks',[])), 'Stop hook missing'; assert 'Bash(python -m n3memorycore.n3memory --search *)' in s.get('permissions',{}).get('allow',[]), 'permission rules missing'; print('OK')"
```

`OK` が出力されればフックと許可は正しく登録されています。`AssertionError` が出る場合は `n3mc --init` を再実行してください。

#### 4. Claude Code を再起動する

実行中の Claude Code セッションを**すべて**閉じて（ターミナル CLI ウィンドウ、VS Code 等の IDE 拡張の "Claude Code" パネル、その他すべて）、新しいセッションを起動してください。フックはセッション起動時に読み込まれるため、`n3mc --init` の前から開いていたセッションには反映されません。

ウィンドウを閉じただけでは、アプリが裏で動き続けていることがあります。Windows では、タスクバーの右端（時計の近く）の「^」を開き、Claude のアイコンがあれば右クリックして終了してください。よくわからないときは、Windows から一度サインアウトして、サインインし直してください（スタートメニュー → 左下の自分のアカウントのアイコン → **サインアウト**）。PC の再起動でもかまいません。

#### 5. 動作確認

新しい Claude Code セッションで何かメッセージを送信し、Claude が応答したあと以下を実行:

```bash
n3mc --list
```

最低 2 件のレコードが表示されるはずです — `[user]` プレフィックス（あなたのメッセージ）と `[claude]` プレフィックス（Claude の応答）。リストが空の場合は下の **トラブルシューティング** へ。

#### オプション: データ位置の変更

`N3MC_HOME=/path/to/dir` を設定すると、データの保存先を変えられます。N3MC は、動くたびにこの変数を読みます。値をどこかに覚えることはありません。そのため、Claude Code（フックを起動します）とターミナルの両方から見える形で、**恒久的に**設定してください（たとえば、ユーザーの環境変数として）。設定は `n3mc --init` の前に行います。`--init` を実行したターミナルにだけ設定した場合、フックは `~/.n3mc` を使います。

### トラブルシューティング（方法 B）

**`pip install` 後に `n3mc: command not found`**
Python の `Scripts/`（Windows）または `bin/`（Linux）ディレクトリが `PATH` に通っていません。`PATH` に追加するか、代替として `python -m n3memorycore.n3memory --init` を使用してください。

**実際に会話したのに `--list` が 0 件**
`n3mc --init` を実行する**前から**開いていた Claude Code セッションを使っています。完全に閉じて新規セッションを起動してください — フックはセッション起動時に読み込まれます。

**フックは登録されているのに何も保存されない**
監査ログを確認してください:
```bash
cat ~/.n3mc/.memory/audit.log | tail -3
```
ユーザープロンプトごとに 1 行 JSON が追加されているはずです。空ならフックが発火していません — Step 3 の検証コマンドが `OK` を返すか、また編集対象が**ユーザーグローバル**の `~/.claude/settings.json`（プロジェクトローカルの `.claude/settings.json` ではない）になっているかを確認してください。

**初回 `n3mc --search` が空を返すが、その後は動く**
`intfloat/multilingual-e5-base` モデル（約 1.1 GB）が初回呼び出し時にダウンロード中です。ダウンロードが終わるのを待ってからリトライしてください。

### セットアップ後の体験

セットアップが完了すると、次のセッションから自動的に動作します：
- あなたの発言に関連する過去の会話が、自動で検索・注入されます
- Claudeは過去の文脈を踏まえて回答します（「前回話した○○ですが…」）
- 保存も検索もバックグラウンドで行われるため、操作は不要です
- Stop フックが、作業したプロジェクトのフォルダごとに、小さなルールファイル `.claude/rules/n3mc-behavior.md` を書きます。呼び出した塊の読み方を Claude に伝えるものです。手で編集したファイルは、置き換えません

### 検索の設定

記憶の呼び出し方は、`~/.n3mc/config.json` の設定で調整できます。主な設定の名前と意味は、指示書に書いてあります。

### バックアップと復元

記憶を別の環境に移行する場合や、安全のためにバックアップする場合は `~/.n3mc/` 配下の以下の 2 ファイルを保管してください：
- `.memory/n3memory.db` — 記憶データ本体
- `config.json` — `owner_id`・`local_id` のUUIDv4キー

この 2 ファイルは、セットで保管してください。`config.json` には、DB の記録に付いている ID が入っています。

### アンインストール

方法 A で導入した場合は、Claude Code に「N3MemoryCore を削除してください」と頼んでください。フックの設定の解除も含めて行います。

自分で行うときは、次の順です。

1. `~/.claude/settings.json` から、2 つのフックの登録（`n3mc-hook`、`n3mc-stop-hook`）と、`n3memorycore.n3memory` または `n3mc` を含む許可のルールを消し、Claude Code を再起動します。
2. 記憶のサーバーを止めます。サーバーは、バックグラウンドで動き続けています。コマンドラインに `n3memorycore.n3memory --run-server` を含むプロセスを終わらせるか（PID は `~/.n3mc/.memory/n3mc.pid` にあります）、PC を再起動します。
3. パッケージとデータを消します。

```bash
pip uninstall n3memorycore-free
rm -rf ~/.n3mc/                                      # データ削除（不可逆）
```

4. プロジェクトのフォルダにある `.claude/rules/n3mc-behavior.md` と、`settings.json` の隣にあるバックアップ `settings.json.bak-n3mc-*` は、手で消してかまいません。

## ID 階層構造

N3MemoryCore は 6 つの ID フィールドで各レコードの出所と文脈を識別します：

| ID | 保存場所 | 生成タイミング | 粒度 | 用途 |
|---|---|---|---|---|
| `id` (PK) | DB レコード | レコード作成時 (UUIDv7, 時系列順) | **1 レコード** | 各記憶の一意識別子 |
| `owner_id` | `config.json` | 初回起動時 (UUIDv4) | **所有者 / データフォルダ** | データの所有者識別 — 共有・マルチユーザーシナリオ・インポート由来の記録に使用 |
| `local_id` | `config.json` / API | 初回起動時 (UUIDv4)、またはリクエスト毎 | **インストール** | 1 つの Claude Code のインストールに 1 つ。どのセッションでも同じ値。全レコードに保存する（Free 版ではランキングには使用されない；`b_local` は Pro 機能） |
| `session_id` | Claude Code から渡される（フックの入力）。なければプロセスごとに作る | 会話ごと | **1 つの会話** | 同じ会話の記憶をまとめる。Free 版では `b_session` ランキングバイアス（一致=1.0、不一致=0.6）を駆動し、進行中の会話を、関係のない過去のセッションより優先する |
| `turn_id` | DB レコード | あなたの発言を保存するとき (UUIDv4) | **1 つのやりとり** | 1 つの発言と、それに答える返答を結ぶ。`--show-turn` と `--recall-thread` に渡す |
| `agent_name` | DB レコード | 保存ごと (任意文字列) | **表示名** | 書いたものの人間可読なラベル（フックは `"claude-code"`）。`--buffer --agent-id <name>` はこのフィールドを入れる |

```
owner_id  (データフォルダ ~/.n3mc と、その所有者)
  └── local_id  (インストール。どのセッションでも同じ)
        └── session_id  (Claude Code の 1 つの会話)
              └── turn_id  (1 つのやりとり: 1 つの発言と、その返答)
                    └── id  (1 件のレコード = 1 つのチャンク)

agent_name  (表示用のラベル。階層の外。フックは "claude-code")
```

## 拡張性

N3MemoryCoreは指示書（仕様書）を読ませて作るため、拡張もClaude Codeに相談するだけで対応できます。

- **MCPサーバー化** — N3MCをMCPサーバーとして公開し、他のAIツールから記憶にアクセス
- **PostgreSQL移行** — SQLiteからPostgreSQL + pgvectorへ（1 人が 1 台の PC で使う既製の版は、PostgreSQL の N3MC Pro、`n3mc-pro-postgres`）
- **カスタム検索ロジック** — バイアス係数やランキング式の調整
- **他のembeddingモデル** — 用途に合わせたモデルへの差し替え
- **キーワード検索のトークナイザー** — 既定のキーワードの索引（FTS5 `trigram` と、日本語・中国語・韓国語のための 2 文字の索引）は、空白で区切らない言語でも、英語のような言語でも動くように選んでいます（PyPI 版はどこの国でも使われるため）。最終的なトークナイザーは、ご自分の言語・環境に合わせて直してください（例: 英語中心なら語形変化をまとめる `porter unicode61`、日本語の精度を上げるなら形態素解析）。起動のときに索引を `trigram` に作り直す確認の直しと、既存の DB の全文検索の索引の作り直しも含めて、Claude Code に相談すれば対応できます
- **ID階層の拡張** — `project_id`や`tag`など、分類フィールドを自由に追加
- **PDF取込** — PDFからテキストを抽出し、検索可能な記憶として保存
- **ハッシュタグ対応** — Claudeが記憶に `#タグ` を自動付与して絞り込み検索（例: `--search "#AWS"`）。既存のFTSで動作し、DB変更不要

指示書をClaude Codeに読ませて「○○を追加して」と伝えるだけです。
